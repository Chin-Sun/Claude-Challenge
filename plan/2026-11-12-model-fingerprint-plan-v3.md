## Context

10 个匿名模型 ID，OpenAI 兼容接口，总共 100 次请求（限次不限额），截止 11-16 10:00。第一题找指定模型（对 +20，错 −10），第二题识别其余模型（名称 +10，版本 +10，错 0）。脚本、框架、模型须在本地运行。排名按"猜对多且请求次数少"。

本质是**黑盒、低预算、开放集的模型识别**，而且主办方是"防守方"，会主动伪装。

## 调研结论对计划的四处修正

1. **最接近的先例是 LLMmap**（USENIX Security 2025）。LLMmap 用约 8 个查询识别 42 个模型版本，准确率约 95%。照搬它的两点：用参考数据按信息增益**挑查询**；参考库采集时**随机套用大量不同的 system prompt 和参数**，让分类器对伪装不敏感。
2. **信号按"能不能伪装"分级加权**：分词器 > 能力 > 知识截止 > 文风 > 自我声明。原因是 system prompt 对行为信号的影响很大（Tosea 实测：仅换 system prompt 的偏移量，和直接换模型一样大），对分词器则没有影响。
3. **"一次请求塞满探针"必须先验证**：打包后答案之间会互相影响。只要参考库按完全相同的方式打包采集，这样做仍然有效，但要在模拟赛里和"拆成 2 次请求"的方案对比后再定。
4. **同家族内部，分词器只能分代，分不了档位**：分档靠首字延迟、生成速度、高难题通过率；分代和版本靠知识截止和分词器。

## 方法组合

| 层 | 内容 | 主要作用 | 来源 |
|---|---|---|---|
| L1 基础设施 | 4 条固定文本（英文、中文、代码、emoji）的 `usage.prompt_tokens`，**以单字符请求为基线做差**，抵消服务端模板带来的额外 token；`finish_reason` 取值、`id` 前缀、`system_fingerprint`、`reasoning_content` 字段（可能被网关改写，只作弱证据） | 厂商、代际 | modelprint、llm-relay-verifier |
| L2 速度 | 首字延迟、每秒 token 数 | 档位 | codex-model-watch |
| L3 能力阶梯 | 程序随机生成参数、答案可程序校验的难题（代码追踪、日历推算、骑士与无赖、中国剩余定理），提示词禁止用工具 | 档位 | ccfingerprint、llm-relay-verifier |
| L4 知识锚点 | 带日期的事件题，推断真实知识截止；检查"自称 X 的模型是否知道 X 截止前的事件" | 版本 | ccfingerprint |
| L5 行为指纹 | 打包的伪随机序列、强制单词作答、拒答措辞 | 精确型号 | LLMmap、Tosea、relay-verifier |
| L6 文体 | 一段自由写作，用本地 TF-IDF + 逻辑回归分类 | 厂商 | llm-idiosyncrasies |
| 决策 | 各层似然相乘得后验；多个 ID 疑似同一模型时合并证据；后验不够就发针对性区分卷 | 停止条件、第一题阈值（后验 > 1/3 才选） | LLMmap、llm-verify、ShadowHunter |

**usage 是否由网关重算的自检**：第一轮结束后检查，10 个 ID 对同一段文本报出的 token 数如果完全相同，并且等于本地 tiktoken 的计数，就说明 `usage` 是网关重算的，L1 的分词器信号作废，权重转给 L2 和 L3。这一步不花额外请求。

## 计数规则带来的约束

- **正式请求只用最保守的参数**：只带 `model`、`messages`、`max_tokens`（适中值）、`temperature`（0 到 1 之间，各家都接受）、`stream: true`。不带 `n`、`logprobs`、`stop` 等可能被某些后端拒绝的参数
- **报错类探针默认不用**：`max_tokens` 超大、`temperature` 越界这类探针依靠的就是"被拒"，每用一次就扣 1 次请求。只有两个候选在其他信号上都分不开，并且报错文本恰好能区分它们时，才作为最后手段
- **`n>1` 默认不用**：据我了解，Claude 的 OpenAI 兼容接口不支持 `n>1`（需查官方文档核实），请求一旦被拒就白扣 1 次
- **客户端重试规则**：只在明确的网络层失败时重试（连接被拒、DNS 失败、TLS 握手失败，这些情况下请求没到达服务器）。收到任何 HTTP 响应，包括 4xx 和 5xx，一律不重试，记入账本。读超时也不重试，因为请求可能已被处理并计数；超时设长（600 秒），用流式接收
- **探针卷要先在本地模拟网关上跑通**，确保不会因为格式问题被拒

## 不采用

- **TRAP**：需要对参考模型做梯度优化，闭源模型做不到
- **统计检验类方法**（单 token 分布、MMD）：样本需求远超预算
- **relay-guard**：把答案上传到服务端判分，违反本地运行约束
- **LLM2vec 分类器**：需要 24GB 显存，Mac 上用 TF-IDF 替代
- **FlashProve**：零知识推理证明，需要服务方配合生成证明，且只支持 Llama 4 Maverick。可借鉴一点：浮点推理跨机器无法逐位复现，所以参考指纹按分布比对，即使 temperature=0 也不要求逐字一致

## 验证方式

1. 模拟网关随机抽 10 个候选模型，藏在 model-a 至 model-j 后面，随机加伪装 system prompt，跑完整流程
2. 按比赛规则自动算分，重复 20 轮以上，报告平均分 ± 标准差、平均请求数、混淆矩阵
3. 分别报告"有伪装/无伪装"和"usage 透传/重算"四种条件下的准确率
4. 达标线：平均分 ≥ 160 且平均请求数 ≤ 20
5. 彩排时核对计数账本与实际发出的请求数完全一致；人为制造网络错误，确认重试规则不会多扣次数
