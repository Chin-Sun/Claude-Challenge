# Claude 注水攻防挑战：实施计划 v4（代码完成后的修订）

> 在 v3 和 `2026-11-12-methodology-selection.md` 的基础上修订，不取代它们。
> 用法见项目根目录的 `README.md`，这里只记录相对 v3 的改动和剩余工作。

## 相对 v3 的改动

| 项目 | v3 | v4 | 原因 |
|---|---|---|---|
| 请求参数 | 带 `temperature`（0 到 1） | 不带 `temperature` 和 `top_p` | 官方文档：Claude 4.7 及之后在 OpenAI 兼容接口上拒绝小于 1 的 `temperature`，被拒也计数 |
| JSON 输出 | 未指定 | 只在提示词里要求，不用 `response_format` | 官方文档：`json_object` 会返回 400 |
| 流式用量 | 未指定 | 带 `stream_options.include_usage` | 流式下不带它拿不到 `usage` |
| `max_tokens` | “适中值” | 16000 | 低于清单里所有候选的输出上限（最小的是 16384） |
| 分词器探针 | 4 条文本各发 1 次再减基线 | 用探针卷自身的 `prompt_tokens`；发过第二份卷子的 ID 用两次的差值 | 原做法每个模型要 5 次请求 |
| 候选清单 | 未定 | 52 个，分三层，见 `candidates.py` | 来自 ppapi 模型列表和 Anthropic 官方列表 |
| 线路 | 假设单一线路 | ppapi 和官方两条线路采集，受线路影响的信号低权重 | 比赛网关走哪条线路未知 |
| 开放集 | 未实现 | 增加“库外模型”候选，用所有模型的合并分布表示 | 清单不可能覆盖全部 |
| 第一题决策 | 后验 > 1/3 就选 | 比较“选中”和“填第二题”的期望得分 | 指定模型后验 40%、同门兄弟 60% 时，填第二题更划算 |
| 首发保护 | 无 | 第一发被拒立即停止 | 避免 10 发全被拒 |

## 验证方式

1. `python3 -m unittest tests.test_all`：账本、重试规则、解析、端到端、断点续跑。
2. `python3 -m sim.evaluate --world replay --split test`：按比赛规则计分的最终估计。
3. 选型规则：先取平均分最高的策略；差距在一个标准差以内时取请求数少的。
4. 彩排时核对账本数与模拟网关的计数一致。
